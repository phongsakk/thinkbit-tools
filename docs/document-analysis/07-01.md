### ชื่อผลิตภัณฑ์ใต้ช่องผลิตพิกัด

- คลังที่ผลิตได้หลายชนิด มักลงชื่อผลิตภัณฑ์เป็นหัวคอลัมน์ย่อย (เช่น `เพาเวอร์ดี` · `ไฮดีเซลเอส`)

- กรณีไม่มีชื่อบนใบ: **ดึงชื่อผลิตภัณฑ์จากฐานข้อมูล**มาประกอบ (ตามคลัง / บริบทวัตถุดิบ) แล้วใส่ใน `pay.taxed_products[].name`  
  พร้อมระบุแหล่งที่มาว่ามาจาก DB ไม่ใช่จากข้อความในใบ

## ความหมายหน่วยและคอลัมน์รับ (โดเมน)

### หน่วย

หน่วยปริมาณหลักคือ **ลิตร**  
บางใบอาจพิมพ์อุณหภูมิร่วมด้วย เช่น `ลิตร (86oF)` — ค่านั้นคือ**อุณหภูมิน้ำมันตอนวัด/บันทึกของใบนั้น** ไม่ใช่ค่ามาตรฐานของแบบ และไม่ใช่อุณหภูมิอากาศ

**อย่าตีความว่า 86°F เป็น default ของ ภส.07-01**  
ใบที่เห็น `86oF` เป็นแค่บังเอิญวัดได้ตอนน้ำมันอยู่ที่ 86°F

ลำดับการตัดสินใจสำหรับ `temperature_f`:

1. อ่านได้จากเอกสารชัดเจน (เช่น `86oF` / `60°F`) → เก็บค่านั้นตามใบ  
2. ใบมีแค่ `หน่วย : ลิตร` หรือไม่ระบุอุณหภูมิ → เก็บ `temperature_f: null` (ไม่ทราบจากใบ)  
3. **ห้าม** เติม 86 จากใบอื่น / จาก “มาตรฐานแบบ” / จากค่าเฉลี่ยอากาศไทย

### B/L และ Outturn

คอลัมน์ **B/L** และ **Outturn** จะมีเมื่อวัตถุดิบนั้นเป็น **base**  
(= ส่วนผสมหลัก / เป็นสัดส่วนมากสุดในผลิตภัณฑ์)

| คอลัมน์ | ความหมาย |
| --- | --- |
| **B/L** | ค่าตามใบกำกับภาษี |
| **Outturn** | ค่าที่วัดได้ตอนรับเข้ามา |

โดยทั่วไป **B/L ≠ Outturn** เพราะแหล่งที่มาต่างกัน (เอกสารกำกับ vs การวัดรับจริง)

ถ้าวัตถุดิบไม่ใช่ base (เช่น สารเติมแต่ง / ส่วนผสมรอง) มักไม่แยกหัว B/L–Outturn — อาจเห็นแค่ปริมาณรับรวม (Pattern A) หรือไม่มีชุด (๖.๑)/(๖.๒)

## Pattern A — Bangchak หัวสั้น (B103 / B104)

### โครงหน้า (บน → ล่าง)

1. **ฟอร์ม** — `ภส.07-01`
2. **หน่วยงาน** — กรมสรรพสามิต กระทรวงการคลัง
3. **ชื่อแบบ** — บัญชีประจำวันแสดงการรับและการจ่ายวัตถุดิบ ตามมาตรา 118 …
4. **เมตาแถว** — `ประเภทวัตถุดิบ : …` + `หน่วย ลิตร` (บางใบมี `(86oF)` = อุณหภูมิน้ำมันตอนวัดของใบนั้น)
5. **แถวกลุ่มหัว**
6. **แถวย่อยชื่อสินค้า** (ใต้ผลิตสินค้าพิกัด)
7. **แถวเปิดบัญชี** — มักขึ้นต้นด้วย `ยอดยกมา`

### หัวตาราง (กลุ่ม)

```
วันที่ | รายการ | หลักฐานเลขที่ | จำนวนรับ
                                   └─ จำนวนจ่าย ─┬─ ผลิตสินค้าพิกัดอัตราภาษีสรรพสามิต
                                                 ├─ ผลิตสินค้าอื่น
                                                 ├─ เสียหาย
                                                 ├─ อื่นๆ
                                                 └─ รวมจ่าย
ยอดคงเหลือ | หมายเหตุ
```

### ตัวอย่างแถวย่อยสินค้า (dynamic)

- ดีเซลเบส → `เพาเวอร์ดี` · `ไฮดีเซลเอส`
- เอทานอล → `แก๊สโซฮอล์ 91 เอส` · `แก๊สโซฮอล์ 95 เอส` · `อี 20 เอส`
- แก๊สโซฮอล์เบส 95 → `แก๊สโซฮอล์ 95 เอส`
- สารเติมแต่ง → อาจเหลือคอลัมน์พิกัดน้อยลง / ชื่อสินค้าเดียว

### สิ่งที่มักไม่มีใน Pattern A

- หัวแยก `B/L` / `Outturn` (แม้วัตถุดิบจะเป็น base ก็อาจถูกยุบเป็น `จำนวนรับ`)
- หัว `ปริมาณสิทธิ์หักลดหย่อน`
- หัว `อัตราภาษี` แยกคอลัมน์
- คงเหลือแยก Stock / ตามบัญชีสิทธิ์ (เหลือ `ยอดคงเหลือ` ก้อนเดียว)

ตัวอย่างวัตถุดิบที่เป็น base ในชุดนี้: ดีเซลเบส, แก๊สโซฮอล์เบส, น้ำมันเบนซิน/ดีเซลพื้นฐาน — ถ้า layout เป็น Pattern B จะเห็น B/L กับ Outturn แยกชัด

## จุดร่วมของทั้งสองแพทเทิร์น

1. เป็นบัญชีรับ–จ่ายวัตถุดิบรายวัน (ภส.07-01)
2. หน่วยปริมาณเป็น **ลิตร** — `temperature_f` มีเฉพาะเมื่อใบระบุอุณหภูมิตอนวัด
3. มีแกนซ้ายคงที่: วันที่ / รายการ / หลักฐาน
4. มีกลุ่ม “จ่าย” ที่แตกเป็นผลิตพิกัด / อื่น / เสียหาย / อื่นๆ / รวมจ่าย
5. มีคงเหลือ + หมายเหตุ
6. แถว `ยอดยกมา` เป็นจุดเปิดงวดบ่อย
7. **ชื่อสินค้าใต้ผลิตพิกัดเป็นคอลัมน์แปรผัน** — ต้อง map แบบ repeatable ไม่ใช่หัวตายตัว
8. **คลังผลิตได้ชนิดเดียว** มักไม่ลงชื่อในช่องผลิต — เติมชื่อจากฐานข้อมูลได้
9. **B/L / Outturn** ผูกกับวัตถุดิบที่เป็น base — ไม่ใช่มีทุกหน้า

| `pay.taxed_products[].name_source` | `"document"` ถ้าอ่านจากใบ · `"database"` ถ้าเติมจากฐานข้อมูล (คลังผลิตชนิดเดียว) |
| `pay.other_product` / `damaged` / `other` / `total_out` | กลุ่มจำนวนจ่ายที่เหลือ |
| `balance.quantity` | Pattern A: คงเหลือก้อนเดียว |
| `balance.stock` / `balance.account_rights` | Pattern B: คงเหลือ Stock / ตามบัญชีสิทธิ์ |
| `remark` | หมายเหตุ |
| `gain` | ผลต่าง / Gain (ถ้ามีแยกจากหมายเหตุ) |

### กฎการเติมค่าตามแพทเทิร์น

**Pattern A**

- ใส่ `receive.quantity_in`
- ตั้ง `receive.bl` / `outturn` / `discount_rights` / `tax_rate` = `null`
- ใส่ `balance.quantity` — `stock` / `account_rights` = `null`

**Pattern B + วัตถุดิบ base**

- ใส่ `receive.bl` และ `receive.outturn` แยกกัน (อย่าบังคับให้เท่ากัน)
- `receive.quantity_in` = `null` (หรือจะเก็บสำเนารวมก็ได้ แต่ไม่แทนที่ bl/outturn)
- ใส่ `balance.stock` และ `balance.account_rights` เมื่อมีสองช่อง

**Pattern B + ไม่ใช่ base** (เช่น สารเติมแต่ง)

- `bl` / `outturn` มักเป็น `null`
- อาจมีแค่ปริมาณรับรวมหรือไม่มีชุดรับละเอียด

**ทุก pattern**

- `taxed_products` ต้องตาม `taxed_product_columns` ของหน้านั้นเมื่อมีชื่อบนใบ
- ถ้าไม่มีชื่อบนใบ (คลังผลิตชนิดเดียว): ใส่ปริมาณจากใบ + เติม `name` จากฐานข้อมูล และตั้ง `name_source: "database"`
- ตัวเลขว่าง / `-` ในเอกสาร → `null`

ตัวอย่างเมื่อเติมชื่อจากฐานข้อมูล:

```json

  "taxed_product_columns": [],
  "pay": {
    "taxed_products": [
      {
        "name": "HSD Premuim",
        "name_source": "database",
        "quantity": 543348
      }
    ]
  }
}
```
